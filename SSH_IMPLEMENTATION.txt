💻 HOW IT WORKS
────────────────────────────────────────────────────────────────────────────────

Architecture:
   Your PC ←──SSH Tunnel──→ Remote Server (134.185.111.151)
                           /home/ubuntu/env-secrets.json
                           (Encrypted JSON)

Operations:

STORE:
   Plain Value → Encrypt (AES-256-GCM) → SSH Upload → Save on Server

RETRIEVE:
   SSH Download → Decrypt (AES-256-GCM) → Return Value → Log Access

DELETE:
   SSH Download → Remove Entry → SSH Upload

LIST:
   SSH Download → Parse JSON → Return Keys (no values)

LOGS:
   SSH Download → Filter by Secret → Return Audit Trail

🔐 SECURITY
────────────────────────────────────────────────────────────────────────────────

✅ Encryption
   • AES-256-GCM (military-grade)
   • Each secret has unique IV
   • Authentication tag prevents tampering

✅ Key Management
   • ENCRYPTION_KEY kept locally
   • SSH_KEY used only for authentication
   • Neither stored with encrypted data

✅ Transport
   • SSH tunnel for all communication
   • Encrypted during transit
   • SSH key authentication (no passwords)

✅ Audit Trail
   • Every access logged
   • Timestamp + User + Action
   • Supports compliance audits

✅ File Permissions
   • Remote file readable only by ubuntu
   • SSH key protected (chmod 600)
   • No world-readable secrets

💡 USE CASES
────────────────────────────────────────────────────────────────────────────────

✅ When to Use SSH File Storage:

1. You have SSH access to a server
2. Don't want external cloud dependencies
3. Need simple, transparent storage
4. Want to keep everything self-hosted
5. Already have server infrastructure
6. Need manual control over backups
7. Want to avoid vendor lock-in

❌ When NOT to Use:

1. Need high concurrency (multiple simultaneous users)
2. Require automatic geo-replication
3. Need 99.99% uptime SLA
4. High-frequency access patterns
5. Prefer fully managed solutions

🛠️ COMMON COMMANDS
────────────────────────────────────────────────────────────────────────────────

Test Connection:
  $ ssh -i /Users/user/.ssh/id_rsa ubuntu@134.185.111.151 "echo OK"

View Remote Database:
  $ ssh -i /Users/user/.ssh/id_rsa ubuntu@134.185.111.151 "cat /home/ubuntu/env-secrets.json"

Backup Database:
  $ scp -i /Users/user/.ssh/id_rsa ubuntu@134.185.111.151:/home/ubuntu/env-secrets.json ./backup.json

Restore Database:
  $ scp -i /Users/user/.ssh/id_rsa ./backup.json ubuntu@134.185.111.151:/home/ubuntu/env-secrets.json

Check Permissions:
  $ ssh -i /Users/user/.ssh/id_rsa ubuntu@134.185.111.151 "ls -la /home/ubuntu/env-secrets.json"

Fix Permissions:
  $ ssh -i /Users/user/.ssh/id_rsa ubuntu@134.185.111.151 "chmod 600 /home/ubuntu/env-secrets.json"
